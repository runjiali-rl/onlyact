# Probe data (Table 1, Table 4, and the LIBERO / RLBench / SpatialVID clips of Table 2)

| file | content |
|---|---|
| `<dataset>.json` | clip list of one dataset: `{"dataset", "tasks": [...]}` in the order the evaluations read it |
| `datasets.json` | per dataset: the action target name and the probe settings (task type, scene field, split mode, variance floor) |
| `prepare/` | one script per dataset that writes the frames, the 128x128 frames and the action targets from the public raw data |

Each task of a clip list has
- `task_id`, `scene_id`, `scene_key` (the held-out unit of the splits; LIBERO and RLBench split by `scene_id`);
- `target_frames`: `paths` (frame files relative to the data root), `frame_indices` (time steps of the clip in the
  source episode; actions are indexed by them), `n_frames`;
- `source`: public identifiers of the raw data the clip comes from (episode, file, video id, frame or pose indices,
  Hugging Face repository and revision). The evaluation code does not read it; the preparation scripts do.

No frames and no action targets are distributed with this repository. Download each dataset from its source and run
its preparation script (below); the scripts write the frames, the 128x128 frames and the action targets.

## Preparing the data

```bash
pip install -r data/probe/prepare/requirements.txt
python data/probe/prepare/<script>.py --raw <raw data> --out $DATA [--limit N | --task_ids ...]
```

writes, with the relative paths of the clip list,

```
$DATA/probe/<dataset>/...                                frames read by the encoders            (Tables 1 and 2)
$DATA/leakage128/<dataset>/...                           128x128 frames of the leakage decoder  (Table 4)
$DATA/eval_data/probe/<dataset>/<target>/<task_id>.npy   action targets of the linear probe     (Table 1)
```

These are the default locations of `scripts/reproduce_table{1,2,4}.sh` with `DATA=$DATA` (`EVAL_DATA` defaults to
`$DATA/eval_data`).

Existing files are kept, so a run can be restarted (`--overwrite` rewrites them). The module docstring of each
script gives the exact input layout, the frame processing and the action definition.

Download and preparation, from the repository root (`<...>` are folders of your choice; `hf` is the command-line
tool of `huggingface_hub`):

```bash
P=data/probe/prepare

# libero: the 52 HDF5 files named by the clips
python -c "import json; print('\n'.join(sorted({t['source']['suite'] + '/' + t['source']['file'] for t in json.load(open('data/probe/libero.json'))['tasks']})))" > libero_files.txt
hf download yifengzhu-hf/LIBERO-datasets $(cat libero_files.txt) --repo-type dataset --local-dir <libero>
python $P/libero.py --raw <libero> --out $DATA

# rlbench: download the 18 archives of train/ from the PerAct Google Drive folder (the PerAct README recommends
# rclone) and extract them so that each episode is <rlbench>/<task>/all_variations/episodes/episode<N>/
python $P/rlbench.py --raw <rlbench> --out $DATA

# droid (IRIS lab); for droid_iprl use --dataset droid_iprl and --labs IPRL. Needs gsutil and ffmpeg.
python $P/droid.py --dataset droid --write_task_ids droid_ids.txt
python data/training/droid_download_and_process.py --labs IRIS --task_ids droid_ids.txt --data_root <droid>
python $P/droid.py --dataset droid --raw <droid>/droid_processed --out $DATA

# robocasa: one video and one parquet file per clip
python -c "import json; print('\n'.join(t['source'][k] for t in json.load(open('data/probe/robocasa.json'))['tasks'] for k in ('video', 'data')))" > robocasa_files.txt
hf download nvidia/PhysicalAI-Robotics-Manipulation-Kitchen-Demos $(cat robocasa_files.txt) --repo-type dataset \
    --revision 522e4ffa3bb9d9729f79b241c65fc9e589f2659c --local-dir <robocasa>
python $P/robocasa.py --raw <robocasa> --out $DATA

# metaworld
python $P/metaworld.py --list_files > metaworld_files.txt
hf download lerobot/metaworld_mt50 $(cat metaworld_files.txt) --repo-type dataset \
    --revision b46a1c185a2368660650a82ac5a5083a56722f48 --local-dir <metaworld>
python $P/metaworld.py --raw <metaworld> --out $DATA

# utaustin_mutex
python $P/utaustin_mutex.py --list_files > mutex_files.txt
hf download IPEC-COMMUNITY/utaustin_mutex_lerobot $(cat mutex_files.txt) --repo-type dataset \
    --revision cced76715b3322c69b4096e3a6a16de1d862207f --local-dir <mutex>
python $P/utaustin_mutex.py --raw <mutex> --out $DATA

# vp2_robosuite and vp2_robodesk
hf download s-tian/VP2 vp2_training_datasets/robosuite/5k_slice_rendered_256.hdf5 \
    vp2_training_datasets/robodesk/robodesk_{flat_block_off_table,open_drawer,open_slide,push_blue,push_green,push_red,upright_block_off_table}/noise_0.1_256.hdf5 \
    --repo-type dataset --local-dir <vp2>
python $P/vp2.py --dataset vp2_robosuite --raw <vp2>/vp2_training_datasets --out $DATA
python $P/vp2.py --dataset vp2_robodesk --raw <vp2>/vp2_training_datasets --out $DATA

# spatialvid_nav: gated, accept the licence on the dataset page and log in with `hf auth login` first
python data/training/spatialvid_download_and_process.py --data_root <spatialvid> --subdir videos --work_dir <tmp> --start 0 --end 8
hf download SpatialVID/SpatialVID annotations/group_000{1..8}.tar.gz --repo-type dataset --local-dir <archives>
python $P/spatialvid_nav.py --extract_annotations <archives>/annotations --raw <spatialvid>
python $P/spatialvid_nav.py --raw <spatialvid> --out $DATA

# arkitscenes: <ARKitScenes> is a clone of github.com/apple/ARKitScenes (Apple's downloader)
python $P/arkitscenes.py --write_video_ids arkit_ids.csv
python <ARKitScenes>/download_data.py raw --split Training --video_id_csv arkit_ids.csv \
    --raw_dataset_assets lowres_wide.traj lowres_wide --keep_zip --download_dir <arkit>
python $P/arkitscenes.py --raw <arkit>/raw/Training --out $DATA
# (or download only lowres_wide.traj and add --remote to the last command: the frames are then read from Apple's server)

# realestate10k
python $P/realestate10k.py --list_files > re10k_files.txt
hf download lhmd/re10k_torch $(cat re10k_files.txt) --repo-type dataset --local-dir <re10k>
python $P/realestate10k.py --raw <re10k> --out $DATA

# procgen_plan: no download; a Python 3.10 environment with the packages listed at the end of prepare/requirements.txt
python $P/procgen_plan.py --out $DATA
```

Each dataset keeps the licence above. Of the data itself, this repository contains only the clip lists (relative frame
paths and public identifiers of the raw data).

## How the clips were chosen

The selection is fixed by the clip lists; the scripts do not re-draw it. For the record:
- LIBERO: 1,403 demonstrations of 52 LIBERO-100 tasks, 41 time steps spread over each demonstration. RLBench: 18 tasks
  x 100 episodes, 41 time steps each.
- DROID and DROID-IPRL: 150 episodes of one lab each, seeded draw; 60 frames from the start of the episode (all steps
  when the episode has at most 120, otherwise 120 evenly spaced steps, of which the first 60).
- RoboCasa: every downloaded episode, the 60 steps in the middle. MetaWorld: 10 episodes per task. MUTEX: 4 episodes
  per task. VP2: 300 demonstrations per dataset. Procgen: 75 episodes per game.
- SpatialVID: the first 300 clips, in (group, clip id) order, of groups 1-8 that are in the encoder's training set and
  have at least 41 annotated poses. ARKitScenes: 280 Training scans in seeded order with at least 178 poses, 60 poses at
  stride 3 centred in the scan. RealEstate10K: the first 300 test videos, in chunk order, with at least 41 frames at
  stride 3.

## Reproducibility

With the package versions of `prepare/requirements.txt`, the scripts reproduce the paper's files byte for byte on the
clips we could re-check:
- frames, 128x128 frames and actions from the public raw data: MetaWorld, MUTEX, RoboCasa, VP2 Robosuite, VP2 RoboDesk,
  Procgen;
- frames, 128x128 frames and actions from the ffmpeg re-encodings made by `data/training/` (DROID and DROID-IPRL JPEG
  frames with the original `trajectory.h5`, SpatialVID 256x256 videos with the original pose annotations);
- actions only, for all clips: ARKitScenes (from the `.traj` files), RealEstate10K (from the official camera files),
  RLBench (from the recorded gripper poses).
The LIBERO, RLBench, ARKitScenes and RealEstate10K frames could not be re-checked against their raw data.
Decoding is deterministic, but colour conversion can change between decoder builds, so other versions of PyAV, decord,
OpenCV or Pillow may change a few pixel values. A different ffmpeg / x264 build can also give slightly different DROID
and SpatialVID frames, because those inputs are re-encodings; the action targets do not depend on it.
